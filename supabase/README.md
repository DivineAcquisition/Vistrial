# Supabase setup

Migrations here are **not** run by the app. Apply them yourself, in order.

## Apply migration 001

1. Open your project in the [Supabase dashboard](https://supabase.com/dashboard).
2. Go to **SQL Editor** → **New query**.
3. Paste the entire contents of `migrations/001_ledger.sql`.
4. Run it. It should complete without errors on a fresh project.

## Then wire the app to it

1. Copy `.env.local.example` to `.env.local` at the repo root.
2. Fill in the three values from **Project Settings → API**:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (server-only, never expose to the browser)
3. Restart `npm run dev` and open `/clients`. You should see the empty table
   rather than the "Supabase not connected" alert.

## Sanity checks after applying 001

```sql
-- webhook_secret is generated by the database default
insert into public.clients (name) values ('Test Roofing Co') returning id, webhook_secret;

-- updated_at is bumped by trigger
update public.clients set status = 'Active' where name = 'Test Roofing Co'
returning status, created_at, updated_at;

-- clean up
delete from public.clients where name = 'Test Roofing Co';
```

## Row level security

Every table has RLS enabled with **no policies**, so only the service role key can
read or write. That is intentional until authentication lands. Server code must use
`createServiceClient()` from `lib/supabase/server.ts`.
